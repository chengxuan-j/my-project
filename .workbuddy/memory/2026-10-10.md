## 修复：传话丢失（首版只推 SSE 不落库，实测失败）
现象：家属端发出成功（日志 `dog_relay: ... 200 OK`），但老人端什么都没有。

根因（从 backend 日志时间线锁定）：
- 老人端当时 SSE 是 `401 Unauthorized`（token 过期/未连上）→ 没有任何订阅者；
- `app/core/events.py` 的 `bus.publish` 只是往 asyncio.Queue 里 put，**没有订阅者时事件直接丢弃**，且不落库；
- 等老人重新登录连上 SSE 时，那条传话已经没了。

修复（落库 + 上线补播，不动表结构，复用 family_messages）：
- `family_message_repo.py` 新增 `list_pending_dog_relays()`：查 `category='dog_relay'` 且未读、按 id 正序。
- `dog.py` `POST /dog/relay`：先用 `FamilyMessageRepo.create(..., category='dog_relay')` 落库并 commit，SSE 事件带上 `message_id`；实时推送照旧。
- `dog.py` 新增 `GET /dog/relays`（require_elderly）：拉取待补播传话，**取出即 mark_read**，避免重复播报。
- 前端 `api.ts` 加 `dogApi.pendingRelays()`；老人端 `page.tsx` 进页面就拉一次（`list.length>0` 取最后一条 `setDogRelay` → 触发 TTS）；SSE 实时收到时 `markRead(message_id)` 保持状态一致；家人留言列表用 `visibleFamInbox` 过滤掉 `category==='dog_relay'`，不重复显示。

回归测试脚本（已加到项目根目录，可重复跑）：
- `test_dog_relay.py`：离线场景→上线补播→二次拉取为空→越权校验（老人调 /dog/relay 返回 403）。全绿。
- `test_dog_relay_realtime.py`：老人端在线发 SSE，家属实时发传话，立刻收到 dog_relay。通过。

教训（重要）：**本项目 `bus.publish` 是不可靠投递——没有订阅者就丢。任何需要"确保对方收到"的实时功能，都必须落库 + 接收方上线后拉取补。**

## 升级：让物理机器狗真正开口（B方案，2026-10-10 完成软件侧）
需求升级：不仅要老人端念，还要物理狗用喇叭把"女儿提醒您：记得按时吃药"念出来。

关键结论（实测）：
- 狗固件 HTTP 面**只有** `/control`(move/action/wake)、`/start_calibration`、`/exit_calibration`、`/adjust`，**无 speak/tts 接口**；且固件不做字段校验（`{"foo":"bar"}` 也回 200，探测会假阳性，别信）。
- 但狗有麦克风+喇叭（ESP-Hi，唤醒词"Hi 乐鑫"），语音链路是云端：狗麦克风→Opus上传→云端ASR/LLM/TTS→Opus下发→狗喇叭。**要狗说话必须往它的 WS 对话链路注入 TTS 音频**。

实现（改 `E:/company/xiaozhi-esp32-server/main/xiaozhi-server`）：
- `core/device_registry.py`（新增）：全局 `device_id → Connection` 注册表，`register_device/unregister_device/get_online_devices`。
- `core/websocket_server.py`：`_handle_connection` 连接时 `register_device(handler.device_id, handler)`、断开时 `unregister_device`。
- `core/connection.py`：新增 `speak_text(text)`，绕过 LLM，直接走 TTS 三段帧(FIRST/MIDDLE/TEXT/LAST)→ `output_audio`→WS。已对齐 `chat()` 现有 TTS 写法。
- `core/http_server.py`：新增 `POST /devices/{id}/say {text}`（调用该设备 `speak_text`）、`GET /devices`（列出在线设备）、OPTIONS 预检。
- `config.yaml`：精简 `selected_module` 到只留 `TTS/LLM/Memory`（避免加载缺依赖的 VAD=Silero/ASR=FunASR/VLLM=QwenVL）。备份在 `config.yaml.bak`。
- 依赖补齐（conda `xiaozhi` 环境）：`edge_tts`、`opuslib_next`、`mcp==1.22.0`；并用 `conda install -c conda-forge libopus` 装 C 库。**启动时必须带 PATH=/d/Anaconda/envs/xiaozhi/Library/bin**，否则 opuslib 找不到 opus.dll。
- `plugins_func/loadplugins.py`：import 插件失败改为 warn 跳过（避免任一插件缺依赖拖垮整体）。
- TTS 默认 `EdgeTTS`（免费免 key），`data/.config.yaml` 已配好。

接回 elderly（让"家属传话"同时驱动狗）：
- `app/api/v1/dog.py`：新增 `push_to_dog(text)`——`GET {xiaozhi_http}/devices`，取首个在线设备 → `POST /devices/{id}/say {text}`；狗未连/不可达时静默返回 False，不影响主流程。
