> 整理时间：2026-10-14
> 用途：把仓库当前的目录构成、跨项目依赖、以及"项目套项目"带来的隐患一次性写清楚，作为后续整理/重构的对照基线。

## 0. 一句话结论

这是一套**「老人情感陪伴 AI」主项目**，根目录 `app/`（FastAPI 后端）+ `web_next/`（Next.js 前端）是真正在维护的主线；
其余 `xiaozhi-server/`、`vision-control/`、`web-control/` 是**为接入 ESP-Hi 机器狗而从外部项目整目录拷进来的附属件**，各自带独立的依赖清单、配置和测试；
`web/` 与 `scripts/legacy/` 是早期遗留。
**当前最需要警惕的不是"看着乱"，而是「本地代码 ≠ 容器里跑的服务」——`docker compose up` 起来的机器狗服务不包含你们自己写的"让狗说话"改动。**

## 2. 四块代码的边界

### 2.1 主线：`app/` + `web_next/`

- 依赖声明：根 `pyproject.toml`（name `elderly-companion`）+ 根 `requirements.txt`，二者内容一致。
- 测试：根 `tests/`（pytest，`testpaths = ["tests"]`）。
- CI：`.github/workflows/ci.yml`（后端 ruff + pytest；前端 npm ci + build）。
- 入口：`run.py` → `uvicorn app.main:app :8000`。
- 数据：`storage/companion.db`（SQLite，开发）/ PostgreSQL（生产，`DATABASE_URL`）。

### 2.2 外来件：`xiaozhi-server/`（230 个文件）

2026-10-13 从外部 `xiaozhi-esp32-server` **整目录复制**进来，**不是一个标准依赖，而是另一套完整的 Python 项目**：

- 自带 `pyproject.toml`、`requirements.txt`（与根目录的完全不同，含 funasr/opuslib 等音频栈）；
- 自带 `config.yaml`（基础配置）+ `data/.config.yaml`（运行期覆盖，**含明文 API Key**）；
- 自带 `docker-compose.yml`、`docker-compose_all.yml`（官方脚手架那份，**未适配本项目**）；
- 自带 `tests/`（另一套 pytest，含 `conftest.py`、`config/`、`core/`）；
- 自带 `models/`、`music/`、`performance_tester/`、`plugins_func/`、`core/providers/{asr,llm,tts,vad,vllm,memory,intent,tools}`。

> ⚠️ 该目录运行需要独立的 Python 环境（funasr 等），与主项目 `.venv` 不是同一个。

### 2.3 外来件：`vision-control/`

同事的 `tools/vision_control` 提取到顶层（见 `docs/机器狗整合规划.md`）。独立 `requirements.txt`，入口 `vision_dog.py`，两种识别后端（MediaPipe / YOLO11-Pose），下发器优先级 `--http` > `--ws` > dry-run。

### 2.4 外来件：`web-control/`

机器狗网页调试台，自带独立 `server.py`（:8080）与 `app.js` / `vision.js`。**不接入真机时的调试用**。

## 3. 跨项目依赖图（谁调谁）

```
浏览器(:3000 web_next)
   │  /api/v1/*
   ▼
app/ (:8000)  ──── dog_control.py ───────────►  ESP-Hi 机器狗固件  POST /control
   │                                            （局域网 IP，如 10.1.56.231）
   ├──── app/api/v1/vision.py ────────────────►  xiaozhi HTTP :8003  /mcp/vision/explain
   │                                            （XIAOZHI_VISION_URL）
   └──── app/api/v1/dog.py:40 push_to_dog() ──►  xiaozhi HTTP :8003
                                                 GET /devices  → POST /devices/{id}/say
                                                        │
                                                        ▼
                                            xiaozhi-server 本地代码：
                                            core/device_registry.py（设备注册表）
                                            core/connection.py:1397 speak_text()
                                            core/http_server.py /devices/{id}/say

vision-control（PC 摄像头）──► ESP-Hi 机器狗  POST /control     ← 与 app 无代码耦合
web-control（调试台）      ──► ESP-Hi 机器狗  /control          ← 与 app 无代码耦合
```

要点：`app` ↔ `xiaozhi-server` 之间有**两处真实耦合**（视觉理解、驱动狗说话），不是单纯的"并排放着"。
`vision-control` / `web-control` 与 `app` **无任何代码依赖**，只共享同一个物理狗。

## 4. 混乱点清单

### 🔴 隐患级（会导致实际故障）

**H1. 容器里跑的不是本地代码，`docker compose up` 后"让狗说话"必然失效。**
根 `docker-compose.yml` 的 `xiaozhi` 服务用的是远程镜像：

```yaml
xiaozhi:
  image: ghcr.nju.edu.cn/xinnan-tech/xiaozhi-esp32-server:server_latest
  volumes:
    - ./xiaozhi-server/data:/opt/xiaozhi-esp32-server/data   # 只挂了配置，没挂代码
```

既没有 `build: ./xiaozhi-server`，也没有挂载 `./xiaozhi-server` 源码。
而 `app/api/v1/dog.py:push_to_dog()` 依赖的 `/devices` 与 `/devices/{id}/say` 接口，**只存在于本地改动**（`core/device_registry.py`、`core/http_server.py:46`、`core/connection.py:1397 speak_text`）——官方镜像里没有。
**后果**：Docker 部署路径下，家属端"让小狗传话"会静默失败（`push_to_dog` 捕获异常后返回 `False`，不报错），物理狗不出声。

**H2. `xiaozhi-server/data/.config.yaml` 含明文 LLM API Key，且已随提交进入公开仓库。**
根因：`.gitignore` 第 17-19 行把注释写在了**行尾**。git 的 `.gitignore` **不支持行内注释**——整行（含 `# ...`）会被当成一个模式，导致 `xiaozhi-server/data/`、`tmp/`、`models/SenseVoiceSmall/` 三条规则**从未生效**（可用 `git check-ignore -v --no-index <path>` 验证）。
2026-10-14 整理时已修复规则，并把该文件移出 git 跟踪（磁盘文件保留）。**但密钥仍留在远端历史的 `first commit` 中，必须作废并重新签发才能消除风险。**本文档不复制其内容。

**H3. 三处端口/地址记录互相矛盾。**

| 来源 | xiaozhi WS 端口 | 说明 |
|---|---|---|
| `xiaozhi-server/config.yaml:12` + `data/.config.yaml` | **8001** | ✅ 实际生效 |
| 根 `docker-compose.yml` | **8001** | ✅ 与实际一致 |
| `xiaozhi-server/docker-compose.yml`（官方那份） | **8000** | ❌ 过期 |
| `docs/机器狗整合规划.md` | **8000** | ❌ 描述的是合并前状态 |

**H4. 文档记录的路径已全部失效。**
`docs/机器狗整合规划.md` 写"均位于 `E:\elderly_companion` 下"；`.workbuddy/memory/2026-10-10.md` 提到改动在 `E:/company/xiaozhi-esp32-server/main/xiaozhi-server`。
而当前实际路径是 `C:\Users\BigGayGod\Desktop\my-project-main`。**照文档找文件会找不到。**
