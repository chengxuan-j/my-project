> 更新时间：2026-10-14（**目录重构后**；上一版基于重构前的扁平结构）
> 用途：记录仓库构成、跨模块依赖、以及仍待处理的问题。所有结论均来自实际读码。

## 0. 一句话结论

项目由**两块**组成，现已分区清楚：

- **陪伴端**：`backend/`（FastAPI :8000）+ `frontend/`（Next.js :3000）
- **机器狗**：`robot/xiaozhi-server/`（早期还有 `vision-control/`、`web-control/`，能力已被前端 `visionEngine.ts` + 后端 dog API 取代，2026-10-14 删除）

项目曾带一套 docker-compose 部署编排（其中"容器里的机器狗服务是坏的"即 H1）——**2026-10-14 已连同整套 Docker 内容一并移除**，该隐患随之解除（见第 3 节）。当前只走本地直接运行。

## 3. 仍存在的问题

### ✅ H1（已解除）：Docker 编排已整体移除

（历史）根 `docker-compose.yml` 的 `xiaozhi` 服务用的是远程镜像，不含本地改动，导致容器路径下"让狗说话"失效。

**2026-10-14：整套 Docker 相关内容已删除**——根 `docker-compose.yml`、`backend/Dockerfile`、`frontend/Dockerfile`，以及 `robot/xiaozhi-server/` 自带的官方两份 compose。项目现在只走本地直接运行，这个隐患随之消失。

若将来重新容器化，务必注意：`xiaozhi` 容器**必须构建本地 `robot/xiaozhi-server/` 源码**，不能用官方镜像——`backend/app/api/v1/dog.py` 的 `push_to_dog()` 依赖的 `/devices`、`/devices/{id}/say` 只存在于本地改动（`core/device_registry.py`、`core/http_server.py:46`、`core/connection.py:1397 speak_text`）。

### 🟡 两套 Python 环境（结构分开了，本质还在）

```
backend/               →  fastapi / langgraph / jose             环境甲（本项目用 backend/.venv）
robot/xiaozhi-server/  →  funasr / opuslib / edge_tts + ffmpeg   环境乙（本机对应 conda 环境 xiaozhi）
```

同一个 `python` 满足不了两者，这也是"启动方式难以统一"的根本原因。

### 🟡 小智的语音输入能力**被主动关闭了**（不是丢失）

`robot/xiaozhi-server/config.yaml` 的 `selected_module` 只留 `LLM / TTS / Memory / Intent`，**VAD 与 ASR 关闭**，文件内注释写明原因：本机环境未装 silero/funasr 等重型依赖，为让服务能启动、只保留「主动让设备朗读（`speak_text`）」。
- 完整版配置备份在同目录 `config.yaml.bak`（含 `VAD: SileroVAD` / `ASR: FunASR` / `VLLM: QwenVLVLLM`）
- 恢复完整对话能力需要三样：恢复 `.bak`、拷回 `models/SenseVoiceSmall`（897M，本机桌面 `mxiaozhi-esp32-server/`、`xiaozhi-esp32-server/` 两处都有）、补齐依赖

### 🟡 legacy API 整套（仅测试在用）

`backend/app/api/routes.py` 有 15 个路由（`/chat`、`/profile/{user_id}`…），与 `/api/v1/*` 是重复实现。`backend/app/main.py` 已标 `deprecated=True`、仅非生产环境挂载。
**前端完全不用**，但 `backend/tests/` 直接依赖它（`test_chat.py` 调 `/chat`、`/memories/{user_id}` 等）——**不能删**。

### 🟡 后端已实现、前端没有入口的接口

| 接口 | 位置 | 说明 |
|---|---|---|
| `POST /api/v1/game/new`、`/api/v1/game/check` | `backend/app/api/v1/content.py` | 益智游戏，后端出题/判题完整，前端**没有游戏页面** |
| `POST /api/v1/feedback/recommendation` | `backend/app/api/v1/feedback.py` | 推荐内容反馈，前端无对应 UI |
| `GET /api/v1/health` | `backend/app/api/v1/health.py` | 探活用，前端不调（保留合理） |

## 4. 跨模块依赖图

```
浏览器 (:3000 frontend)
   │  /api/v1/*  （由 next.config.js rewrites 代理）
   ▼
backend/ (:8000)
   ├── app/services/dog_control.py ──────────►  ESP-Hi 机器狗固件  POST /control
   │                                             （局域网 IP，如 10.1.56.231）
   ├── app/api/v1/vision.py ─────────────────►  robot/xiaozhi-server HTTP :8003
   │                                             /mcp/vision/explain（XIAOZHI_VISION_URL）
   └── app/api/v1/dog.py:40 push_to_dog() ───►  robot/xiaozhi-server HTTP :8003
                                                 GET /devices → POST /devices/{id}/say
                                                        │
                                                        ▼
                                        robot/xiaozhi-server 本地改动：
                                        core/device_registry.py（设备注册表）
                                        core/connection.py:1397 speak_text()
                                        core/http_server.py:46 /devices/{id}/say
```

要点：`backend` ↔ `robot/xiaozhi-server` 之间有**两处真实耦合**（视觉理解、驱动狗说话）：
`backend/app/api/v1/vision.py` 把老人端照片转发给小智做图像理解；
`backend/app/api/v1/dog.py` 的 `push_to_dog()` 调用小智的 `/devices/{id}/say` 让狗开口。

## 5. 配置事实核对表

| 项 | 值 | 出处 |
|---|---|---|
| 后端 | `http://127.0.0.1:8000` | `backend/run.py` |
| 前端 | `http://127.0.0.1:3000` | `frontend/next.config.js` / README |
| 小智 WS | `ws://<本机IP>:8001/xiaozhi/v1/` | `robot/xiaozhi-server/config.yaml` |
| 小智 HTTP（OTA + 视觉） | `http://<本机IP>:8003` | 同上 `http_port` |
| 视觉理解接口 | `{XIAOZHI_VISION_URL}` 默认 `http://127.0.0.1:8003/mcp/vision/explain` | `backend/app/config.py:67` |
| 机器狗固件 | `{DOG_BASE_URL}` 默认 `http://10.1.56.231`，接口 `/control` | `backend/app/config.py` / `robot_action.py` |
| 主项目 LLM | DashScope 公网端点 + `qwen-plus`（可调） | 根 README / `.env.example` |
| 小智 LLM | 阿里云 MaaS 私有点 + `qwen3.8-flash` | `robot/xiaozhi-server/data/.config.yaml` |

> 主项目与小智是**两套完全独立的 LLM 配置**，改一处不会影响另一边。
