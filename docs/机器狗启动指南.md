# 机器狗语音+动作 启动指南

> 前提：固件已刷好，`CONFIG_OTA_URL` 指向本机服务器（见文末「固件侧配置」）。
> 本文档描述的是**真机 ESP32 狗自己发声陪聊 + 做动作**的完整启动流程。

---

| 项 | 值 |
|---|---|

| WebSocket（语音通道） | `ws://10.1.57.128:8001/xiaozhi/v1/` |
| OTA / HTTP 接口 | `http://10.1.57.128:8003/xiaozhi/ota/` |

## 二、一键启动（推荐）

双击 **`docs` 目录里的 `启动_全功能.bat`**。它会：
1. 检查 `8001/8003` 是否已被占用，避免重复启动后端
2. 把 ffmpeg/opus.dll 加进 PATH（音频编解码必需）
3. 在两个独立窗口分别启动**后端**和**前端网页**

等「后端」窗口出现这行就表示就绪：
```
Websocket地址是    ws://10.1.57.128:8001/xiaozhi/v1/
```

关闭：直接关掉那两个 cmd 窗口。

---

## 三、让机器狗接入

1. 确认狗和电脑在**同一局域网**（狗刷固件后 WiFi 要配好）。
2. 给狗上电开机。它会自动：
   - 请求 `http://10.1.57.128:8003/xiaozhi/ota/`
   - 拿到 WebSocket 地址后连上 `ws://10.1.57.128:8001/xiaozhi/v1/`
3. 后端窗口出现 `xxx conn - Headers:` 日志，说明狗连上了。

接下来对狗说话即可：
- **陪聊**：「你好呀」「今天天气怎么样」→ 狗用自己的扬声器回你
- **做动作**：「握个手」「往前走」→ 狗做动作
- **连续动作**：「先向前走再握手」→ 狗依次执行

---

## 四、手动启动（不想用 bat 时）

打开 PowerShell，分两个窗口：

**后端：**
```powershell
Set-Location robot\xiaozhi-server
$env:PATH = 'D:\miniconda3\envs\xiaozhi\Library\bin;' + $env:PATH
& 'D:\miniconda3\envs\xiaozhi\python.exe' app.py
```

**前端（可选）：**
```powershell
Set-Location robot\web-control
& 'D:\miniconda3\envs\xiaozhi\python.exe' server.py
```

> 如果 LLM 访问需要代理，只设置 `HTTPS_PROXY`，并把本机与机器狗地址加入 `NO_PROXY`；先确认代理服务实际运行。

## 五、验证链路（狗没反应时排查）

```bash
# 1) 后端端口在监听？
netstat -ano | grep -E ":8001|:8003"

# 2) OTA 能返回正确的 ws 地址？（模拟设备请求）
curl -s -X POST http://10.1.57.128:8003/xiaozhi/ota/ \
  -H "Device-Id: 11:22:33:44:55:66" -H "Client-Id: test-001" \
  -d '{"application":{"version":"1.0.0"},"board":{"type":"esp-hi"}}'
# 期望返回含 "websocket":{"url":"ws://10.1.57.128:8001/xiaozhi/v1/"...}

# 3) 机器狗动作接口通？
curl -s -X POST http://10.1.56.231/control -H "Content-Type: application/json" -d '{"action":"7"}'
# 期望 {"code":200}，狗会握手
```

| 现象 | 可能原因 |
|---|---|
| 狗连不上、后端无 conn 日志 | 狗 WiFi 没连、狗 IP 已变化；或固件 OTA 地址与电脑 IP 不符 |
| 普通请求返回校园网登录页 | Windows 存在经有线网去往 `10.1.56.0/24` 的路由；网页转发和动作插件会绑定同网段 WLAN 地址 |
| 网页显示“机器狗未连通” | 机器狗可能已从 Wi-Fi 掉线；检查供电和 `RANGE` 网络，再刷新状态 |
| 能聊天但没声音 | 后端 TTS 报错；或 ffmpeg/opus 没进 PATH（用 bat 启动可避免） |
| 说动作只闲聊不执行 | LLM 没调工具（检查 `.config.yaml` 人设是否被覆盖） |
| 动作能做但一直走不停 | 正常已修复：move 类走 1.5s 自动停（见 `robot_action.py`） |
| LLM 超时/无回复 | 代理没开或 7890 端口不通（`HTTPS_PROXY` 检查） |

## 六、固件侧配置（刷机时用，仅记录）

固件仓库：`D:\xiaozhi-esp32`（`78/xiaozhi-esp32`）
关键配置写进 `sdkconfig.defaults`：
```
CONFIG_OTA_URL="http://10.1.57.128:8003/xiaozhi/ota/"
CONFIG_WEBSOCKET_URL="ws://10.1.57.128:8001/xiaozhi/v1/"
```
> 用 **http**（明文）指向本机，绕开厂商云的 HTTPS 证书校验问题。

编译烧录（需 ESP-IDF 环境）：
```bash
python ./scripts/build.py espressif/esp-hi
idf.py flash
```
> ⚠️ ESP-Hi 烧录：断开身体只留头部、按住按钮再连电脑（舵机占用了 USB Type-C）。

## 七、两套方案对照（别混淆）

| | 声音从哪出 | 用途 |
|---|---|---|
| **真机 ESP32**（本文档） | 狗自己的扬声器（Opus 音频链路） | 正式使用 |
| **网页调试台**（127.0.0.1:8080） | 电脑扬声器（浏览器朗读） | 没接真机时调试 |

音频链路（真机）：
```
狗麦克风 → Opus上传 → FunASR识别 → qwen3.8-flash → EdgeTTS合成 → Opus下发 → 狗扬声器
                                        ↓ 识别到动作意图
                                   robot_action → POST /control → 狗做动作
```

## 八、快速开始总结

1. **确认前置**：conda 环境 `xiaozhi` 装好、ffmpeg 在 `Library/bin`、代理开着（7890）
2. **双击 `docs\启动_全功能.bat`** → 等「后端」窗口显示 `Websocket地址是...`
3. **给狗上电** → 狗自动请求 OTA → 拿到 ws 地址 → 连上后端
4. **对狗说话** → 狗用自己的扬声器回你，也能做动作

排查看「五、验证链路」，或查日志 `robot/xiaozhi-server/tmp/server.log`。
